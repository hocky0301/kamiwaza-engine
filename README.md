# カミワザ — その紙、30秒で「動くシステム」になる。

[![ci](https://github.com/hocky0301/kamiwaza-engine/actions/workflows/ci.yml/badge.svg)](https://github.com/hocky0301/kamiwaza-engine/actions/workflows/ci.yml)

手書き帳票・FAX注文書・点検表の**写真1枚**を「仕様書」とみなし、その場で実働する業務アプリ
(フォーム / 一覧 / 承認フロー / ダッシュボード)を自動生成します。生成と同時に、紙に書かれていた
内容が1件目のデータとして登録されます。設定画面はありません。

AI HACKATHON 2026 TOKYO 提出作品(**Team OO**・ソロ参加)。

- 解説記事(Zenn): https://zenn.dev/hocky3/articles/2b3b638a8d6885
- デモ動画(YouTube): https://youtu.be/LkqsL06g0Ts

設計判断の理由は [ARCHITECTURE.md](ARCHITECTURE.md)、セキュリティ設計(注入対策の実測含む)は [SECURITY.md](SECURITY.md)、残っている限界・未実装は
[KNOWN_ISSUES.md](KNOWN_ISSUES.md) に先に書き出してあります。コードリーディングの時間が
限られている方は、ARCHITECTURE.md 末尾の「主張とコードの対応表」(主張→実装ファイル→テスト)
から辿るのが最短です。

## 仕組み(30秒版)

```
紙の写真 ─→ 回転検出(tool_use強制・非ゼロは二重合議) ─→ Claude Vision 解析
              └─ SSEストリーム: 部分JSONが届くそばからUIが組み上がる
出力は AppSpec DSL(全階層 additionalProperties:false の制約付きJSON)のみ
  ─→ 決定論レンダラーが描画(LLMに生コードは書かせない)
自由文の再構成(「8万円超の発注は社長承認に」)も閉じた6種の操作に変換して適用
```

- **生成の自由度と実行の安全性の分離**: LLMの出力はデータ(AppSpec)であってコードではない。
  描画・集計・検算はすべて決定論のTypeScript
- **デモとライブの対称性**: 両経路が同一のSSEイベント列を流すため、ライブ障害時は
  デモリプレイへ自動フォールバックして画面を止めない。切替は「ライブ解析に失敗したため、
  デモデータで続行します」と画面に明示し、以降のデータが撮った紙由来でないことを
  誤認させない設計です
- **三重の防御**: フェンス耐性の部分JSONパーサ / アプリ側スキーマ検証+最小要件 /
  done.spec との照合復元。各層が何を拾えないかまで ARCHITECTURE.md に書いてあります
- **読めなかったときの動線**: 読み取り信頼度が低い項目は断定せず、生成直後のアプリが
  逆質問として提示。「いいえ」でその項目ごと除外されます
- **原価の可視化**: usage実測 × OrcaRouter `/v1/models` のライブ単価で「この解析の推定原価」を
  画面に表示(キャッシュは公式掛け率 read 0.1× / write 1.25×。課金の正はダッシュボード)。
  表示されるのは**ライブ解析時のみ**——デモ再生はLLM非経由なので、実測していない額を
  画面に出さない設計です

自由文の適用はAPIキーがあるときはLLM(tool use)、無いときはキーワードの縮退動作で、
縮退側は語彙が狭く上の例文そのままでは通りません(同じ内容は提案チップから確実に適用できます。
詳細は KNOWN_ISSUES.md 1-4)。

## 動かし方

Node 20.9 以上(動作確認は 22.x / npm 10)。

```bash
cd app
npm install
npm run dev   # http://localhost:3000
```

**APIキーなしでデモが最後まで動きます**(5シナリオの決定論リプレイ・ネットワーク不要)。
実物の紙のライブ解析を有効にする場合は `app/.env.local` に以下を設定:

```
ORCAROUTER_API_KEY=sk-orca-...   # 推奨(OrcaRouter経由)
ANTHROPIC_API_KEY=sk-ant-...     # 障害時の直結保険(LLM_FORCE_DIRECT=1 で強制)
```

```bash
npm test        # 859 passed | 1 skipped(skipはライブAPI実測プローブ)
npx tsc --noEmit && npm run lint
```

ブラウザなしで確認する場合(キー不要・SSEイベント列がそのまま流れます):

```bash
curl -N -X POST localhost:3000/api/analyze \
  -H 'Content-Type: application/json' -d '{"scenarioId":"chumonsho"}'
```

## 検証実績

検証コーパスは実在企業1社・2001〜2026年の実書類 14,608件(5.2GB)。75%が定型帳票で、
最大顧客1社の納品・請求だけで4,606件——ピーク年は約720枚、営業日に3枚のペースで紙が
届いていた計算です。この分布が「どの帳票から自動化する価値があるか」の仕様を決めました。

そこから実スキャン帳票50枚(手書き見積FAX・貿易定型帳票・印字納品FAX・複写伝票スキャン・
様式多様な仕入請求書の5類型×各10枚、シード固定で抽出)をライブ解析し、約50体の採点
エージェントが原本画像と照合しました。

| 指標 | 値 |
|---|---|
| 全項目正解(帳票単位) | 96%(48/50) |
| 値レベル精度 | 99.87%(1,516/1,518) |
| 紙に無い値の捏造 | 検出0件(2周・通算2,225値) |
| 明細行の抽出 | 196/196(欠落ゼロ) |
| 解析時間 | 中央値27.3秒/枚 |

この表の限定を先に書いておきます。

- 50枚は**スキャン画像**での検証です。手持ち撮影(影・斜め・ブレ)での精度は未検証で、
  ライブ経路の実走はE2E通過の確認までです(2026-08-11 実測。KNOWN_ISSUES.md 3-6)
- 採点は**LLM採点**で、採点器自体の妥当性検証(人手採点との一致率)は未実施。「捏造0件」は
  採点器が検出した捏造が0件、という意味です。元画像を保存しておらず同一セットの再実行は
  できません(KNOWN_ISSUES.md 3-3)
- 精度数値は直接 Anthropic 経路での実測で、モデル・経路が変われば持ち越せません
  (KNOWN_ISSUES.md 3-2)。コーパスが1社由来である偏りも 3-7 に書きました
- v1→v2 で 38/50→48/50 に改善しましたが、変更は3変数同時で単一要因の統制になっておらず、
  退行も1件あります。統計的な有意性はここでは主張しません

## リポジトリ構成

```
app/                Next.js 16 + React 19。プロダクト本体
  src/lib/          AppSpec DSL / 解析ストリーム / 部分JSONパーサ / 原価推定 ほか
  src/lib/__tests__ vitest 859件
tools/cost-batch/   原価計測バッチ(5枚連続解析→usage集計→ダッシュボード突合)
tools/survey-tally/ 需要アンケートの集計(規則を回答前にスクリプトへ固定: n<20は%非表示・PII非出力)
ARCHITECTURE.md     設計判断の記録(なぜその形にしたか+主張→実装→テストの対応表)
KNOWN_ISSUES.md     既知の問題と限界(直っていないものを先に言う)
```

## データの扱い

- **撮影画像・読み取った記入値はサーバーのディスクに書き込まない**。画面表示はブラウザの
  メモリのみで、再読込で消える
- ファイル書き込みは**監査ログ1経路のみ**(`var/audit.jsonl`・gitignore済み)。残すのは
  ハッシュとメタデータ——どのフィールドが低信頼で逆質問し、人が何番を選び、specがどう
  変わったか。**画像・記入値・ラベル文字列は含まない**(規律の定義とテストは
  [app/src/lib/audit.ts](app/src/lib/audit.ts)・`audit.test.ts`)。`AUDIT_LOG=0` で無効化
- 経路は 自サーバ → OrcaRouter → モデル提供元。OrcaRouterは公式ドキュメントに
  「ディスクに書き込まない・学習に使わない」と明記(その先は各社のポリシーの範囲)
- 本構成は会場デモ前提のローカル起動のみ。`/api/analyze` に認証はなく、公開サーバーへの
  配備は想定していません(配備するなら認証とレート制限が先です。KNOWN_ISSUES.md 2-4)
- 検証に使った実書類・分析原本はこのリポジトリに含めていません(匿名化した集計のみ)
